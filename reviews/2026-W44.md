### 1. Stale Instruction Files Override the Code in Coding Agents: A One-Sentence Fix

**Try · 15m** · fits Claude Code workflow, workflow kit · from digest 2026-10-25 · [arXiv](https://arxiv.org/abs/2610.30571)

A paper tested 40 Python projects where the instruction file asks for one convention and the code uses another. Without a fix, 90.1% of agent choices followed the stale file. One sentence in the user-level instruction file giving existing code precedence raised code-following from 4.2% to 91.4% and test pass rate from 89.4% to 100%.

**Why you:** You rely on CLAUDE.md in every repo, including the workflow kit installed across your projects, so stale instructions are a real risk. A one-sentence user-level change is cheap, and the paper measured it on Claude Code.

**First step:** Read the paper for the exact wording of the sentence, then add a similar sentence to your user-level instructions and watch whether agents stop following outdated conventions on your next few tasks.

### 3. What the Specification Did Not Say: Specification-Oracle Gaps in Test-Graded Coding-Agent Benchmarks

**Read later · 15m** · fits Claude Code workflow · from digest 2026-10-25 · [arXiv](https://arxiv.org/abs/2610.30635)

A paper defines a specification-oracle gap: benchmark tests that need names, paths or messages the task description never states. On SWE-Milestone, 25 of 98 milestones had such a test, and affected build units failed in 80.6% of runs versus 48.4%. The ranking held up, but scores shifted. The authors release an audit tool.

**Why you:** You rely on review gates and evals of agent workflows. This shows how a test-graded benchmark can reward guessing upstream names, which is useful when judging benchmark claims. No project needs action now.

**First step:** Skim the abstract and method section to note the failure pattern, so you can check whether your own plan acceptance tests state every name they depend on.
