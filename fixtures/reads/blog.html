Splitting a reviewer into a fresh-context subagent

We moved code review out of the main agent session into a subagent that starts with no conversation history. It reads only the task, the plan and the diff.

Over four weeks the fresh reviewer flagged 31 issues the in-session review had missed, mostly missing failure handling and tests that mirrored the implementation.

What we changed

The reviewer gets read-only tools and a fixed output format with severities. The main session must fix material findings and re-run the checks before calling work done.

reviewer: tools: Read, Grep, Bash (read-only)

The cost was about 15% more tokens per task, which the team judged worth it. Fixture text for tests.
